## Контрольные вопросы
1. Имя компьютера не хранится в коде. Во время выполнения программа запрашивает его у операционной системы через 'Environment.MachineName', а Windows хранит это имя в своих настройках.
2. ОС работает посредником между программой и оборудованием. Она управляет процессором, памятью и файлами и по запросу программы через API отдаёт ей сведения о системе, процессе и пользователе.
3. «64-битная ОС» работает на 64-битной архитектуре процессора. Она может адресовать гораздо больше памяти, чем 32-битная, для которой предел около 4 ГБ, и запускать 64-битные программы.
4. 'Environment.ProcessorCount' показывает число логических процессоров, которые видит ОС. Оно не обязано совпадать с числом физических ядер: при Hyper-Threading или SMT одно ядро выполняет два потока, поэтому логических процессоров часто вдвое больше.
5. WorkingSet показывает только ту физическую память, которую сейчас занимает процесс вашей программы. Это небольшая часть всей оперативной памяти компьютера, которую делят ОС и все запущенные программы.
6. Код одинаковый, но значения программа получает от ОС во время выполнения, а на каждом компьютере ОС сообщает о своём оборудовании и настройках. Поэтому имя, пользователь, число процессоров и память различаются.

## Итоговый вывод
программа не обращается к оборудованию напрямую: сведения о компьютере она получает у операционной системы во время работы. Поэтому одна и та же программа на разных компьютерах показывает разные результаты: код одинаковый, а значения выдаёт ОС конкретного компьютера.
